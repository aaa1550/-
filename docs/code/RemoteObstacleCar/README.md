# code.txtと同じピン：RemoteObstacleCar（長押し・define版）

**元のcode.txtとピン番号をすべて一致させ、長押し中のみ走行し、前方15cm以内で段階的な警告、5cm以下で強制後退、後方検知で前進する版です。** 前のFlowchartRobotは5cm以下で停止する参考版でした。今回使うのは`RemoteObstacleCar.ino`です。

`code.txt`と同じように、ピン・リモコン値・距離・PWM速度・時間を先頭の`#define`へまとめました。この`.ino`だけで使え、独自のヘッダーファイルは不要です。外部ライブラリはIRremoteのみ必要です。Servoライブラリは使用しません。

## 動作

|入力・条件|動作|
|---|---|
|上（24）|前進|
|下（82）|後退|
|右（90）|右旋回|
|左（8）|左旋回|
|OK（28）|停止。自動回避中でも優先|
|前方15cmより遠い|ブザー停止、通常のリモコン操作|
|前方5cm超〜15cm以内|距離に応じてブザー。方向はリモコン操作を保持|
|前方5cm以下・後方に障害物なし|リモコンの方向を上書きして強制後退|
|後方検知・前方5cm超|リモコンの方向を上書きして前進|
|前方5cm以下・後方も検知|前後がふさがっているため停止|
|超音波無応答|停止。安全な距離として扱わない|

## 長押し操作

方向ボタンを押している間だけ走行し、離すと停止します。リモコンには通常、ボタンを離したことを知らせる信号がないため、長押し中の繰り返し受信を監視します。

- 同じ方向・同じ送信元の有効な繰り返し信号で走行を継続します。
- 最後の有効な信号から`HOLD_TIMEOUT_MS=250`ms以上途切れたら停止します。離した瞬間の停止ではなく、最終受信から約0.25秒とループ処理時間を含む遅延があります。
- 自動後退・自動前進中も、長押しをやめたら停止します。
- OKは受信したら停止指令にします。
- 停止後は古いリピート信号だけでは走り出しません。方向ボタンを離して、押し直します。
- 知らないキー、違う送信元・方向のリピートでは期限を延長しません。受信オーバーフロー・パリティ異常・未知の通信方式は停止にします。
- NEC/NEC2の長押し信号を同じ通信方式として受け付けます。実物のリモコンが長押し中に繰り返し信号を送るかは、実機確認が必要です。

長押し中に止まってしまう場合は、実機の受信間隔や受信状態を確認してから`HOLD_TIMEOUT_MS`を調整します。長くすると、ボタンを離してから止まるまでの時間も長くなります。


起動直後・OK停止中は、障害物があっても自動で走り出しません。距離によるブザーは停止中も鳴ります。方向ボタンの長押しが有効な間は、手動の後退・旋回中でも、前方5cm以下なら後退、後方検知なら前進を優先します。

## ブザーの鳴らし方

|前方距離|1回の周期|ON時間|OFF時間|
|---|---:|---:|---:|
|15cm|600ms|35ms|565ms|
|10cm|350ms|35ms|315ms|
|5cm以下|100ms|35ms|65ms|

5〜15cmの間は距離に比例して周期を短くします。15cmより遠ければ鳴りません。`delay()`を使わず、`millis()`で鳴動を管理するため、ブザーの待ち時間でリモコンとモーター制御を止めません。LOWで鳴るアクティブブザーを想定しています。

## 回避後の動作

- 前方による強制後退は、前方が15cmより離れたら停止します。
- 後方による自動前進は、後方検知がなくなったら停止します。
- 自動回避中にOKを押すと停止します。
- 回避は最大3秒で打ち切って停止します。異常時に走り続けないための初期値です。
- 回避完了・異常・打ち切り後は、古いリモコン指令を解除します。方向キーをいったん離して押し直すと操作できます。
- 回転方向が変わるモーターは、一度PWMを0にして100ms後に新しい方向へ出力します。

回避の終了条件・最大時間・方向切替時間・速度は、今回の説明に数値指定がなかったため追加した設定です。先頭の`#define`から変更できます。

## ピンを変えずにサーボを正面へ向ける方法

通常のServoライブラリはUNOのTimer1を使用し、右モーターD9のPWMと競合します。そのため、この版はServoライブラリを外し、元のサーボ信号D5へソフトウェアで短いパルスを出します。Timer1やPWMの設定レジスターを書き換えないため、右D9・左D6の速度制御を維持できます。

- `SERVO_CENTER_US=1500`：正面付近へ向けるパルス幅の初期値。実物に合わせて微調整します。
- `SERVO_PERIOD_US=20000`：目標周期20ms。他の処理、特に超音波待機で周期が延びる場合があります。
- 1回のパルス出力中は約1.5ms待機します。割り込みは止めず、IR受信とArduinoの時刻管理は継続させます。
- `micros()`で経過時間を監視し、単純な待ち命令に割り込みの遅延が累積することを避けます。それでも割り込み終了待ちやI/O処理によるパルス幅のずれは生じます。
- 起動時は停止したまま約400ms正面合わせし、その後も正面保持用のパルスを出します。左右を見回すサーボ操作は含めません。

これは元のピン配置を保つための制御方法の変更です。実物サーボの正面角度・保持・振動は未検証です。超音波センサーが正面を向いているかを確認して使用してください。

画像6.jpgではIR受信D10、配線.jpgではTrig D10ですが、それぞれ別の接続例です。このプログラムは画像を混ぜず、元のcode.txtのIR受信D4・Echo D3・Trig D10を維持します。

D0はUSBシリアルのRXと共用なので、本プログラムではSerialを使用しません。書き込みに失敗する場合は電源を切ってD0の後方センサー信号線を外し、書き込み後に再接続します。D0を避ける場合は、実配線と`#define LFSensor_bl`を両方A5などの空きピンへ変更します。

後方は左右どちらかの入力がLOWなら障害物ありとします。5チャンネル追跡センサーの資料だけでは、後方障害物センサーとして使えるかは確定できません。取り付けと極性は実物で確認してください。

電源の資料ではブザーVCCは3.3V、超音波とIR受信は5V、サーボはModel X側の5Vです。実物の表記も確認し、GNDを共通にします。

## 速度の初期値

`ADVANCE_SPEED=128`、`BACK_SPEED=77`、`TURN_SPEED=77`、`AVOID_SPEED=80`です（0〜255のPWM）。前進約50%、後退・旋回約30%、回避約31%の初期値であり、実測した車速ではありません。車輪を浮かせて方向と停止を確認し、回避速度で確実に動き出すか確認してから調整してください。

## Arduino IDEで開く

`RemoteObstacleCar.ino`を開き、ボードをArduino Unoにします。IRremote 4.4.1でビルドを確認する構成です。Servoライブラリは不要です。ZIPでは同名のRemoteObstacleCarフォルダへ配置しています。独自ヘッダーの追加は不要です。

## 検証の範囲

本番の`.ino`を模擬I/Oで直接実行し、15cm/5cmの境界、強制後退、後方からの前進、ブザー周期、STOP、前後同時、方向切替停止、超音波失敗、長押し継続・解除、期限境界、古いリピートの拒否、送信元照合、回避中の長押し解除、回避上限、時計の折り返しをテストしています。UNOビルド結果は同梱BUILD_CHECK.mdに記録します。

実機走行・配線・検知距離・センサー極性・ブレーキ距離は未確認です。超音波は60ms周期で読み、`pulseIn()`は最大15ms、サーボのパルス出力は約1.5ms待機するため、検知・停止には遅延があります。5cmでの物理的な衝突防止を保証する値ではありません。
