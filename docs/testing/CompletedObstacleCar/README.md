# 完成コードの単体テスト

保存済み「単体テストサンプル」のテストパターン.xlsxにある「初期化・スタブ・入力・出力・パターン」の形式を使い、CompletedObstacleCar.inoの15関数について105パターンを作成・実行しました。

- 対象：前方10cm以下で後退、後方検知で前進、回避PWM100、通常PWM180、サーボなしの版。
- ソース固定版：https://github.com/aaa1550/-/blob/04d73faf9bcff6b2040f9e3b0d16825a374071cc/docs/code/CompletedObstacleCar/CompletedObstacleCar.ino
- テスト対象ソースの変更はありません。ソースのコピーをtestsに同梱し、実行結果を再現できます。
- 105件はすべてホスト模擬テストで期待値と一致しました。実機テストの合格を示すものではありません。
- 実機の未解決事項：後方赤外線センサーは前進へ切り替わるが、検知が遅く障害物へ接触するとのユーザー報告があります。検知距離・実際の後退速度・100ms反転待ち・障害物の材質などは、現物で確認する必要があります。

## Excelの読み方

mainシートはloop（全体処理）を対象とし、残り14シートは各関数を対象にしています。各パターンは上段が項目名、下段が設定値・結果です。

- C～J：入力・前提条件（最大8枠）。共通初期値を上書きして設定します。
- K～Q：期待出力（最大7枠）。
- R：目的・実施区分。
- S～Y：実行したホスト模擬テストの出力。
- Z：期待出力と実行出力を比較するExcel式。
- 空き枠の「—」はそのケースの確認対象外です。
- 距離の小数は小数第3位で比較しています。echo=579/580/581us（10cm前後）、869/870/871us（15cm前後）を含みます。

期待出力と実行出力の一致判定・合格件数はExcel式で更新されます。入力セルを変えてもC++のテスト本体は自動実行されません。入力を変えたテスト結果を更新するには、下記のテストコードを変更・再実行してください。実機の未確認項目を模擬結果で合格扱いにしないでください。

## 再実行

GCC/G++を使えるPCで、このフォルダーから実行します。

```sh
g++ -std=c++11 -Wall -Wextra -Werror -Itests/stubs tests/unit_tests.cpp -o unit_tests
./unit_tests > results.ndjson
```

標準エラーに `TOTAL=105 FAILED=0` が出力され、各パターンの入力・期待値・実測値はresults.ndjsonへ保存されます。実行は105件の独立したケースで、各ケースの前に状態を初期化しています。

## スタブ

Arduino.h：millis、pinMode、digitalRead、digitalWrite、analogWrite、delayMicroseconds、pulseInを模擬し、引数と呼び出し回数、PWMと端子状態を記録します。

IRremote.hpp：decode、resume、beginと受信データを模擬します。実物のIRremoteライブラリやUNOの割り込み・電気的特性は再現しません。

元サンプルのmain.c/stub.cは別のマイコンのADread/getSW向けの例なので、このArduinoスケッチのテストでは使いません。元の公開保存ZIPはそのまま保持しています。
